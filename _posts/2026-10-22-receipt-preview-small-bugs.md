> **상황** 출력물 요청을 처리하다 영수증 미리보기와 실물 인쇄에서 작은 버그 세 개를 만났다.
>
> **원인** 미리보기를 자른 CSS, 내용을 무시하는 '한줄공백' 플래그, CP949에 없는 반각 원화 기호였다.
>
> **결과** 옵션 조합 10가지로 장별 결제금액 합이 통합본과 같은지 확인했고, 실물 컷팅, 단체 건, 전 전표 취소 경우는 검증하지 못한 채 끝냈다.
{: .tldr}

## 상황

출력물 요청이 몇 가지 들어왔다.

- 정산 내역서를 대분류별로 나눠 한 장씩 출력하기
- 금액 영수증 하나의 날짜와 양식
- 번호표 양식

이 ERP의 영수증 레이아웃은 코드가 아니라 DB 설정(줄 단위 마스터와 조각 단위 상세)으로 관리되고, 인쇄 유틸이 그것을 감열 프린터 명령으로 바꾼다. 반면 화면 미리보기는 컴포넌트에 하드코딩된 템플릿이다. 이 차이가 아래 버그들의 배경이었다.

## 1. 두 번째 영수증이 안 보였다

"품목별 분리 출력" 체크박스를 만들면서, 처음에는 분리를 프린터 출력에만 적용하고 미리보기는 통합본 그대로 뒀다. 화면으로 테스트해 보니 뭐가 바뀐 건지 전혀 알 수 없어서, 미리보기도 장별로 나눠 보여 주도록 고쳤다. 그런데 체크하면 첫 장만 보이고 둘째 장이 없었다.

처음에는 데이터를 의심했지만, 데이터는 두 장 다 만들어지고 있었다. 원인은 이 팝업 전용 CSS였다.

```css
.section-04 .section-body { overflow: hidden; }
.section-04 .body-box     { height: 100%; overflow: auto; }
```

첫 영수증 박스가 미리보기 영역 높이를 다 차지해서, 둘째 장은 렌더링은 됐지만 잘린 영역 밖에 있었다. 영수증들을 스크롤 래퍼로 감싸고 각 박스는 `height: auto`로 덮어써 해결했다. 실제 프린터 출력은 CSS와 상관없는 경로라 영향이 없었다.

장별 내용을 만들 때 반응형 상태를 잠깐 바꿨다 되돌리던 방식도, 렌더 중 재평가가 반복될 위험이 있어 필터를 인자로 받는 함수를 computed가 돌려주는 형태로 바꿨다. 이후 **옵션 조합 10가지**를 미리보기로 돌려, 장별 결제금액 합이 통합본과 같은지 확인했다.

## 2. 넣은 줄이 인쇄되지 않았다

번호표에 큰 번호를 넣으려고 영수증 설정 화면에서 빈 줄에 번호 조각을 추가했는데, 실물에는 아무것도 나오지 않았다. 그 줄에는 **'한줄공백' 플래그**가 켜져 있었고, 인쇄 유틸은 이 플래그가 켜진 줄의 내용을 무시하고 빈 줄 하나만 내보낸 뒤 return했다. 원래 빈 줄이던 자리를 재사용한 탓이었다.

그다음 실물을 요청받은 샘플과 나란히 두고 보니 크기와 비율이 전혀 달랐다. 그때부터 목표가 "요소가 들어가는가"에서 "비율과 구성이 같은가"로 바뀌었다. 글자 크기 목록에 큰 배율이 없던 이유도 이때 알았다. 인쇄 모듈은 더 큰 배율을 지원하지만, 공통코드에는 세 단계만 등록돼 있었다.

## 3. 원화 기호가 역슬래시로 찍혔다

한 영수증에 "일금 일십오만원" 같은 한글 금액이 필요했다. 인쇄 엔진의 변수 타입은 날짜·숫자·전화번호뿐이고 숫자 타입에 문자열을 넣으면 NaN이 돼서, 웹에서 완성된 문자열을 변수로 넘기게 했다.

출력해 보니 금액 앞의 원화 기호가 `\`로 찍혔다.

- 반각 ₩(U+20A9)는 **CP949에 없는 문자**라 인코딩에 실패해 0x5C로 대체됐다.
- 전각 ￦(U+FFE6)는 CP949에 있어 제대로 나왔다.
- 프린터 언어 설정은 이미 한국어였다.

같은 영수증의 미리보기는 날짜를 `new Date()`로 찍고 있어서, 지난 이용 건을 재출력하면 날짜가 출력일로 바뀌었다. 이것은 이용일 기준으로 고쳤다.

## 돌아보면

| 그때는 | 지금이라면 |
|---|---|
| 화면 안에서 생긴 문제를 데이터부터 의심했다 | 개발자 도구로 둘째 장 요소가 있는지부터 볼 것 같다 |
| 원래 빈 줄이던 자리에 번호 조각을 넣었다 | 줄을 재사용하기 전에 그 줄의 플래그부터 확인해 볼 것 같다 |
| 미리보기(코드)와 실물(DB 설정) 중 번호표 미리보기만 실물에 맞췄다 | 한쪽을 고칠 때 다른 쪽도 같이 대조해 볼 것 같다 |
| 실물 컷팅, 단체 건, 전 전표 취소 경우는 검증하지 못하고 끝냈다 | 그 경우들을 먼저 확인 목록에 올려 둘 것 같다 |
{: .compare}

미리보기는 코드, 실물은 DB 설정이라는 이원 구조는 그대로라서 한쪽만 고치면 다시 어긋난다. 이번에는 컴포넌트 주석에 그 사실을 적고 번호표 미리보기를 실물에 맞춰 고치는 데서 멈췄다.
